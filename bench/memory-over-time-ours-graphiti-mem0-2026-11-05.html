Memory over time: an object and its timeline

Our bitemporal memory vs Graphiti (open-source core of Zep) vs Mem0 OSS · live measurements, 5 Nov 2026 · Anton Dziatkovskii

The problem we test

An object changes: a hotel room is empty, then a guest checks in, then checks out; a sales lead is hot, then cools down. A good memory must (1) keep the whole history instead of overwriting it, (2) close the old fact with a date when a new one arrives, (3) answer "what was true on date D", and (4) undo a fact that was recorded by mistake, bringing the previous one back.

Why we pass S3: in our design the end of a fact is not stored, it is derived at read time from the next fact in the chain, so retracting a mistake automatically revives the previous value. Graphiti, like ours, uses two time axes (valid time and record time).

Fair reading: Graphiti did extract all 30 episodes and correctly closed old facts with dates (example: Lead A "band Now" got an end date the moment "This month" arrived). Most misses came from retrieval: in this smoke run we used a simple word-hash embedder instead of a real embedding model, so search often returned another lead's facts. A run with a real embedder (multilingual-e5) and a direct timeline check without search is in progress.

What this means

  • For data that is already structured (CRM, job pipeline), a trigger-based history in the existing database is exact, instant and free. An LLM memory layer adds cost and recall errors there.
  • Graphiti's strength is the step we do not have yet: turning raw text (calls, chats, notes) into dated facts automatically. That is what we want to borrow.
  • Retracting a mistaken fact is a real gap in Graphiti's core and a natural question for any memory vendor.

Questions for Mem0

  2. How do you undo a memory that was extracted by mistake, and does the previous value come back?
  3. What do you recommend for data that is already structured: ingest it as text, or keep it in our DB and let Mem0 only handle conversations?
  4. Which benchmark do you trust for temporal questions (knowledge updates, "as of" questions), and what is your number on it?
